The apple game

So far, our programs have had one or two classes. This week we'll write the apple game, which has four classes that work together.In the apple game, apples fall from the top of the screen and you catch them in a basket. Press Run, then move the basket with the left and right arrow keysthe buttons under the game.

These are the four classes

  • Rectangle is a rectangle drawn on the screen
  • Basket is the rectangle you move
  • Apple is a rectangle that falls
  • Game keeps track of the basket, the apples and the score

The engine module

A game has to draw on the screen and check the keyboard. The engine module will do that for us, and we only need four functions from it.

engine.rect(x, y, width, height, color)Draws a rectangle engine.text(message, x, y)Draws text engine.key_down("left")Is True while that key is held down engine.run(game)Starts the game

A color is a string like "red", and a key is a string like "left" or "space".

The screen

The screen is 600 wide and 300 tall. To draw a rectangle, we have to say where it goes, and we do that with two numbers called x and y.Drag the rectangle to see its x and y change.

  • x is how far the rectangle is from the left side
  • y is how far the rectangle is from the top, so a bigger y is lower on the screen
  • x and y give the position of the rectangle's top left corner

update and draw

To use the engine, we write a class that has two methods, update and draw. The engine calls them 30 times every second, and each time is called a frame.

  1. update is where we change things, and here it adds 3 to self.x
  2. draw is where we draw things. The engine erases the screen first, so the rectangle looks like it's moving.
  3. The last line makes a Game object and gives it to the engine

The Rectangle class

The basket and the apples are all drawn as rectangles. So we start with a class called Rectangle, and the other classes will inherit from it.

  1. The constructor saves where the rectangle is, how big it is and what color it is
  2. draw draws the rectangle on the screen

Using a Rectangle

A class doesn't do anything until we make an object from it. Here the Game class makes one rectangle and draws it.

  1. The game makes a rectangle and saves it in self.basket
  2. Nothing moves yet, so update only has pass
  3. The engine calls the game's draw, which calls the rectangle's draw

Press Edit the code and try a different color.

The Basket class

The basket should move when we press the arrow keys, but a Rectangle can't move. So we write a class called Basket that inherits from Rectangle and adds an update method.

  1. super() runs Rectangle's constructor, and we pass in the basket's x, y, width, height and color
  2. update moves the basket left or right while an arrow key is held down
  3. The engine only calls the game's update, so the game has to call the basket's update

The Apple class

An apple is also a rectangle. An apple starts at the top of the screen, and its update method moves it down.

  1. An apple is given its y when it's made, and random.randint(0, 580) picks a random x
  2. update moves the apple down by 3 every frame
  3. The game makes one apple at the top of the screen
  4. The game calls the apple's update and draw, the same as the basket's

Press Run a few times to see the apple fall from different places.

More than one apple

Now we want two apples falling at the same time. We could save them in two attributes, but then update and draw would need a line for each apple. A list is easier.

  1. The two apples go in a list. The second apple has a y of -150, which is above the top of the screen, so it shows up a little later.
  2. The loop calls update on each apple in the list
  3. The loop calls draw on each apple in the list

Press Edit the code and try adding a third apple to the list.

Checking if two rectangles touch

The game needs to know when the basket catches an apple, which is when the two rectangles touch. So we add a method called touches to the Rectangle class.Drag the apple onto the basket and watch the result change.

def touches(self, other):
    return (self.x < other.x + other.width and
            self.x + self.width > other.x and
            self.y < other.y + other.height and
            self.y + self.height > other.y)
  • basket.touches(apple) is True when the basket and the apple overlap, and False when they don't
  • Inside the method, self is the basket and other is the apple

    Catching apples

    When the basket touches an apple, the player gets a point. The apple then goes back to the top of the screen and falls again.

    1. back_to_top moves the apple to the top of the screen, at a new random x
    2. When the basket touches an apple, we add 1 to the score and send the apple back to the top
    3. self.score starts at 0 in the constructor. To draw the score, we use str() to turn the number into a string.

    Game over

    Right now, nothing happens when you miss an apple. We want the game to end when an apple reaches the bottom of the screen, so we add an attribute called game_over.

    1. When game_over is True, update returns right away, so nothing moves
    2. An apple with a y of more than 300 has fallen off the bottom of the screen, so the game is over
    3. draw shows a message when the game is over

    Press Run to play again.

    Jumping

    In the homework, the player has to jump. Press Run, then press space to see how this box jumps.

    1. The box starts on the ground. GROUND is the y of the ground and the box is 40 tall, so the box's y is GROUND - 40.
    2. speed_y is how fast the box is moving down
    3. jump sets speed_y to -15, which moves the box up, but only if the box is on the ground
    4. Every frame, speed_y goes up by 1. The box slows down on the way up, falls back down and stops at the ground.
