Why use classes?

Say we're making a game with dogs. Every dog has a name and an age, and it can bark. Right now we'd probably use a dictionary and a separate function.

What we'd do now
What we're going to build

The dictionary works, but the dog and the function aren't connected. We're going to make a Dog type so every dog has a name, an age and a bark method, the same way every string has .upper().

Class and object

A class is like a blueprint. It describes what every dog has and what it can do, but it isn't a dog. An object is a dog made from that blueprint.

class Dog
every Dog hasnameage
every Dog canbark()

You only write the class once, but you can make as many dogs as you want, and each dog keeps track of its name and age separately.

Attributes

An object can have variables, called attributes. rex.name means the name that belongs to rex. It's a lot like rex["name"] in a dictionary, but with a dot.

Every object is separate

Changing an attribute on Bella doesn't change Rex, because they're two separate objects.

Setting attributes by hand

Setting attributes one at a time works, but it takes a lot of lines and it's easy to forget an attribute.

The constructor

Setting attributes by hand means writing the same lines for every dog. Instead, we can give the class a constructor, which is a method that Python runs automatically every time you make a new object. In Python the constructor is always called __init__.

Without a constructor
With a constructor

Both versions make the same dog. With the constructor, the name and age are set as soon as the dog is made, so you can't forget either of them.

Reading the constructor

Here's what each part of the constructor does.

Passing values to the constructor

When you write Dog("Rex", 3), Python makes a new empty dog and passes it into the constructor as self. Then "Rex" and 3 go into name and age, in the same order you wrote them.

That's why Dog("Rex", 3) only has 2 values even though __init__ has 3 parameters.

How an object is made

What is self?

The class is written once for every dog, so the code inside it can't say rex.name because it doesn't know which dog it's setting up. self means whichever object it's working on right now.

name vs self.name

Methods

A method is a function inside a class. Every dog can use it, the same way every string can use .upper().

  • The first parameter is always self
  • self.name gets the name of whichever dog it's working on
  • You call it with a dot, like rex.bark(), and Python passes in self for you

Calling a method

When you call rex.bark(), Python passes the object before the dot in as self.
